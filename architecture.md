# News Pulse architecture

A code-linked overview of the root News Pulse public frontend. This describes current wiring, not a production-readiness certification. Follow [rules.md](./rules.md) for contribution and safety requirements, and [BRAIN.md](./BRAIN.md) for source-of-truth policy.

## 1. Application boundary

The root [package.json](./package.json) defines a Next.js 16 / React 19 application using TypeScript, Tailwind CSS 3, and Framer Motion, with Node.js 22.x required. The lockfile determines installed dependency versions.

- The application uses the **Pages Router**, rooted at [pages/](./pages/), not an App Router tree.
- Rendering is mixed: [the homepage](./pages/index.tsx) and [article detail](./pages/news/[slug].tsx) use server-side props; routes such as [business](./pages/business/index.tsx) use static props through [categoryPageProps.ts](./lib/categoryPageProps.ts). Client hooks refresh public data after hydration.
- Next.js API handlers live in [pages/api/](./pages/api/). Many proxy backend endpoints; others implement frontend-owned behavior such as settings compatibility, authentication fallback, or upload integration.
- The main news/admin backend is a separate service. Its DEV/PROD database contract is described in [BACKEND_ENV_SEPARATION.md](./BACKEND_ENV_SEPARATION.md); the public frontend is not the backend deployment or database schema.
- Root scripts launch Next.js, not [server/](./server/) or the nested [newspulse-app/](./newspulse-app/) projects. Do not assume every top-level directory belongs to the active web application.

## 2. Request and rendering flow

```text
Browser
  +-- page navigation --> Next routing / proxy --> page and application providers
  +-- /api/... --------> Next API handler ------> backend or external service
  +-- /public-api/... -------------------------> rewrite to backend
  +-- /public/broadcast/... -------------------> Next broadcast API handlers

SSR / static page loaders --> shared data helpers --> configured backend
Initial page props --------> client state ---------> later refreshes
```

The exact path matters:

- [proxy.ts](./proxy.ts) handles backend-driven SEO redirects, locale routing, and blocking legacy PWA endpoints. It skips API routes and Next internals.
- [next.config.js](./next.config.js) configures locales, image sources, redirects, rewrites, and response headers. It disables automatic trailing-slash redirects.
- [vercel.json](./vercel.json) adds deployment-specific rewrites, headers, and API function duration limits. Its public broadcast rewrites contain a fixed production backend target.
- The homepage ticker [stream](./pages/api/public/broadcast/stream.ts) is not the Live TV video transport. It returns one no-store SSE snapshot per request, with a six-second shared upstream deadline. The [ticker hook](./hooks/usePublicBroadcastTicker.ts) lets EventSource reconnect after five seconds; `Last-Event-ID` yields a `ping` when unchanged. Incomplete connections still use the HTTP/version-refresh fallback. Live TV playback and schedules use their separate [page and public APIs](./pages/live-tv.tsx).
- Browser calls through [lib/publicApiBase.ts](./lib/publicApiBase.ts) use an empty base so requests reach same-origin API routes. Server-side calls can go directly to the configured backend instead of making a loopback request to Next.js.

### Backend selection

The shared resolver in [lib/publicApiBase.ts](./lib/publicApiBase.ts) and the related configuration logic in [next.config.js](./next.config.js) prefer:

1. The explicit `NEXT_PUBLIC_API_BASE` override.
2. The appropriate `NEXT_PUBLIC_API_BASE_DEV` or `NEXT_PUBLIC_API_BASE_PROD`.
3. Supported legacy aliases.

Production is identified using `VERCEL_ENV=production` or the explicit `NEWS_PULSE_DEPLOYMENT` / `NEWS_PULSE_ENV` production values, not `NODE_ENV` alone. The shared resolver can use the known production backend when production configuration is absent; normal non-production use returns no base and warns when missing or when a known production target is refused.

**Boundary:** not every outbound request uses this resolver. [proxy.ts](./proxy.ts) has a separate SEO-redirect resolver with a production fallback, [vercel.json](./vercel.json) has fixed rewrite destinations, and [reporterAuthProxy.ts](./lib/reporterAuthProxy.ts) supports reporter-specific targets. Review those paths explicitly when checking environment isolation; do not infer a universal guard from the shared helper.

## 3. Application shell and source layout

[pages/_app.tsx](./pages/_app.tsx) imports global styles and fonts and composes:

- Theme, public settings, public mode, and feature-flag providers.
- The route-driven language provider, cookie-consent provider, and `next-intl` compatibility bridge.
- Public-version watching, route-language synchronization, SEO alternates, shared navigation, Firebase foreground messaging, and analytics integrations.
- A reporter-auth provider around protected reporter pages.

Aurora is the public default in all editions. [The document](./pages/_document.tsx) restores a consented `np_style` choice (or the legacy `theme` value) before paint; `system`, device settings and published presets do not opt readers into Midnight. [ThemeContext](./utils/ThemeContext.tsx) keeps both style controls and the root `dark` class aligned, and writes preferences only on an explicit selection with preference consent.

[The shared BrandTopHeader](./src/components/layout/BrandTopHeader.tsx) is mounted once by [the application shell](./pages/_app.tsx) on its existing category/header routes, topic archives and Sponsored Content archive. It owns the logo, navigation drawer, route-based language selection and existing style controls; archive pages retain their own title, description, cards and pagination below it.

[pages/_document.tsx](./pages/_document.tsx) owns the document shell and includes one static `google-adsense-account` meta tag in the global head for AdSense site verification. This tag does not load advertising scripts or enable Auto Ads; existing advertising consent gates remain unchanged. Page-level layouts and content remain in the individual page/component trees.

## 4. Main feature and data flows

### News, categories, and article detail

The [homepage](./pages/index.tsx), [category feed](./components/CategoryFeedPage.tsx), [national routes](./pages/national/), [regional routes](./pages/regional/), and [article routes](./pages/news/) share news/domain helpers:

- The [revalidation webhook](./pages/api/revalidate.ts) runs after Backend cache eviction and the public-version bump. For article deliveries (`articles` tag or a news-detail path), no-store article/Home renders, SSR topic/Youth routes and Latest/Search shells have no article ISR entries: they are reported as `skipped`, not regenerated. The Regional redirect targets its actual `/regional/gujarat` listing. Cached listings (including previous categories) and unrecognized explicit targets keep their locale and path.
- The webhook runs at most two regenerations at once under one four-second budget, inside the caller's five-second timeout. Only confirmed completions are `revalidated`; failures return 503, and unfinished or unstarted work returns 504. Next cannot cancel a started regeneration. Retry the authenticated invalidation with the `articles` tag and failed paths, not Save Update.
- [publicNewsApi.ts](./lib/publicNewsApi.ts) fetches news, unwraps backend response shapes, passes language/category parameters, and filters publicly published items.
- Editorial ranking uses the sponsorship identity guard in [sponsoredContent.ts](./lib/sponsoredContent.ts), not campaign visibility or ordinary tags, keywords, categories and headlines. Explicit sponsorship flags/types and sponsored-feature relationships exclude paid articles from Home Top Story, Fresh Stories, ordinary sections, Spotlight, category/Regional hierarchies, National Most Read, localized Youth Pulse trending, Featured Dialogue/editorial contribution cards and article recommendations. Campaign dates/statuses do not turn paid articles into editorial news. Public News/detail APIs, topic archive membership, sponsored placements/disclosures, display slots and ticker ads retain their separate contracts. Pagination metadata is validated before ranking exclusions; ordinary/Regional reads can advance filtered pages within their existing deadline, while Faith retains each fixed backend page.
- Sponsored placement eligibility is separate from paid-article identification. Explicit inactive campaign states and the existing start/end window veto positive activity flags in [publicSponsoredFeature.ts](./lib/publicSponsoredFeature.ts); an explicitly active Feature is not rejected merely because it is not an Article. Publicly eligible sponsored articles retain their existing badge, attribution and disclosure after promotional activity ends, while campaign-dependent placements and sponsor CTAs remain activity-gated. Publication and locale eligibility still control article access; campaign inactivity never grants or revokes publication.
- [Sponsored Content](./pages/sponsored-content.tsx) is a separate locale-aware public archive at `/sponsored-content`, `/hi/sponsored-content` and `/gu/sponsored-content`, not an editorial category or main-navbar entry. [Its scoped reader](./lib/publicSponsoredNews.ts) uses the public News DTO and `sponsoredOnly=true&lang=<locale>&page=N&limit=12`. SSR uses the configured public backend; browser refreshes use the same-origin News proxy. The validated opt-in bypasses ordinary locale widening, filtering and regrouping. Membership requires the exact boolean `isSponsoredArticle` or `isSponsored`; campaign activity is irrelevant. Nonpublic, wrong-locale, ordinary, duplicate or malformed pages fail as a whole instead of changing backend counts, boundaries or order. Backend `page`, `limit`, `total` and `totalPages` drive normal Previous/Next navigation and page-aware SEO. Public-version refreshes and manual retries are cancellable and deadline-bound; transport failures retain same-locale verified content with an alert, while contract violations discard it. Initial failures are no-store 503/noindex responses, never successful empty archives. This contract requires backend support; local fixtures are not proof of its production deployment. Existing Sponsored Feature placements, detail disclosures/CTAs, editorial ranking, display slots and broadcast systems remain separate.
- Archive presentation follows the returned page's item count: one card is centered with an image-left/content-right layout from tablet widths, while multiple cards use one mobile column, two tablet columns and up to three desktop columns. Single-card images retain the shared loader and fallback but use archive-only natural sizing without image padding, grey framing or hover cropping. The image reserves a 16:10 ratio while loading, then uses its own intrinsic proportions; an exhausted fallback retains the shared placeholder. Multi-card image fit and framing are unchanged. Titles and summaries remain complete, attribution and category/date metadata remain visible, and Previous/Next controls appear only when backend `totalPages > 1`. Presentation never changes eligibility, page size, counts, article URLs, SEO or advertising.
- Its article read boundary accepts both legacy translation-content objects and public News `translations` locale-availability booleans. Availability flags are metadata, not translated title/body content or permission for cross-locale fallback. Malformed content and failure envelopes remain rejected. [Article SSR](./pages/news/[slug].tsx) shares its maximum 5.5-second read allowance between article detail and optional recommendations, prioritizing detail and limiting recommendations to the remaining time and at most 1.5 seconds. When a legacy [ID detail](./pages/api/public/news/[id]/index.ts) is already public and visible in the requested locale, its optional translation-group refresh uses only the time left in the proxy's four-second budget (at most 1.5 seconds). A group read needed to resolve the edition retains its 1.5-second allowance; an outage is not proof of absence. SSR retains 404/pending handling and retryable 503 UI, with safe reason-only server diagnostics for unavailable reads. Client pending-translation recovery starts after route reset and bounds each read, including its body, to four seconds while retaining the ten-attempt limit.
- The [Business Pulse page](./pages/business/index.tsx) exposes one locale-aware Sponsored Content link below its existing desk description through [CategoryFeedPage](./components/CategoryFeedPage.tsx). This is Business-only navigation to the separate archive, not a subcategory, content type or feed filter. It reuses the header's small-link styling and Next locale handling without changing Business reads, article URLs, sponsorship labels, global navigation or advertising.
- [localizedArticleFields.ts](./lib/localizedArticleFields.ts) controls localized content and visibility. [newsRoutes.ts](./lib/newsRoutes.ts), [articleSlugs.ts](./lib/articleSlugs.ts), and [storyIdentity.ts](./lib/storyIdentity.ts) coordinate links and identity.
- Legacy [News proxy](./pages/api/public/news.ts) widening retains a valid requested-locale primary representation when an unscoped read serializes the same ID/version in another language. Newer records, same-locale edits and lifecycle withdrawals still use the existing freshness resolution; request counts, deadlines and group ordering are unchanged. Backend-selected localized top-level content does not require a legacy nested translation object.
- [HomeRightRail.tsx](./components/home/HomeRightRail.tsx) supplies the shared Home/category feed mapper. It uses strict localized fields without restoring rejected source text, records the selected display locale, and keeps persisted article identities/slugs. Strict selection never assumes English when source-language metadata is absent or unsupported.
- [Latest](./pages/latest.tsx) is an editorial-only, bounded 40-record request window at `/latest`, `/hi/latest` and `/gu/latest`, not a paginated archive or infinite-scroll feed. It applies the shared strict locale policy and sponsored-identity guard before storing items, preserving encounter order, native-language originals and complete approved/legacy translations; EN/HI also accept complete READY title/body variants, matching Regional's policy. It deliberately keeps the legacy reader's candidates instead of using the proxy's no-READY strict mode, then rechecks the same Latest policy during rendering and locale changes. Existing request cancellation, no-store reads, proxy deadlines, canonical links and layout remain unchanged. Empty eligible windows and read failures retain distinct states. Category badges resolve canonical identities through the locale dictionaries without changing stored values, slugs or independent palettes. No upstream total/page metadata is retained or displayed: generic News totals precede the proxy's logical-story selection/widening and cannot describe a strict editorial archive. Reliable full-archive pagination requires backend locale eligibility/selection, sponsored exclusion and logical-story deduplication before counting and pagination; filtering a client page cannot supply that contract. The general public News API and dedicated Sponsored Content archive remain separate and unchanged.
- Both Trending Strip renderers use [useTrendingTopics.ts](./hooks/useTrendingTopics.ts) for locale-aware reads and public-version refreshes. [The proxy](./pages/api/public/trending-topics.ts) reads editorial topics and shortcuts concurrently with bounded deadlines. Editorial labels, `/topic/<slug>` selections and collision precedence are independent of shortcut policy. Arrays and top-level `items` are already-public links. For a Backend `success/data.items` envelope, [the reader](./lib/getTrendingTopics.ts) requires `destinationPolicyVersion: 1` and uses the exact `publicHref`, never the stored `href`, to navigate. It does not infer authorship or maintain a second live policy map. An older, unavailable or invalid Backend uses the existing nine SSR/offline shortcuts; after a good read, `legacyReadError` preserves known shortcuts while allowing fresh editorial selections. Shared legacy destinations are not deduplicated. The unused `src/lib` override loader is not part of this flow.
- [publicEditorialTopics.ts](./lib/publicEditorialTopics.ts) consumes the stable public topic detail and paginated article DTOs for Trending Topic Story Management V2. The backend alone resolves explicit exact `News.tags` membership (such as `topic:navratri-2026`), public eligibility, requested-locale logical-story selection and newest-first order. The frontend never discovers members from headlines, content, SEO metadata or category. A valid pin is separate from ordinary items and their totals.
- Topic cards and pins use the backend-selected record's locale-owned canonical slug through the shared [article slug resolver](./lib/articleSlugs.ts) and [URL builder](./lib/newsRoutes.ts), matching the article page. A verified Backend ID fallback takes precedence over a seemingly valid but colliding slug. Missing/foreign slugs use the supported article ID; no title-derived slug, foreign-locale substitution or local edition selection is performed. Stored primary slugs and the selected article/group identity are not rewritten.
- [The topic route](./pages/topic/[slug].tsx) seeds its archive through SSR and keeps fixed 12-story Previous/Next pages, with no 12-story archive cap. Mixed-category cards retain their real category and localized category label, normal canonical article links, and backend order; ID/translation-group duplicates and pin repetitions are suppressed only in presentation, without rewriting pagination totals. `tech` uses the Science & Technology label/route identity; `tech-gadgets` stays separate. The existing public-version subscription rereads the mounted page and detail with cancellation and deadlines; failed surfaces retain their last valid content with an alert, never an apparent successful empty refresh. Only successful empty results display "No stories yet."
- Explicit `?q=` article-tag links retain the legacy keyword page. Without `q`, a backend topic-detail 404 returns a page 404 rather than guessed keyword membership; other initial failures return an observable 503/noindex state. A mounted authoritative absence removes the archive without keyword fallback. Starts/Active eligibility and pin eligibility remain backend-owned; expiry removes strip promotion, not an otherwise eligible permanent archive. Editorial canonicals/alternates remain page-aware; explicit tag-search SEO, category ISR/revalidation and sitemaps are unchanged.
- Headline and Latest-page styling use canonical identity from [categoryKeys.ts](./lib/categoryKeys.ts), preferring category-object slugs and reusing route aliases. Translated labels remain display-only. [storyTitleHook.ts](./lib/storyTitleHook.ts) owns headline-prefix colours and splitting; badge, side-strip, navigation, and archive palettes remain independent. `tech` resolves to `science-technology`, not `tech-gadgets`; unknown headline categories and Pulse Dialogue retain the existing blue fallback.
- [regionalInitialStories.ts](./lib/regionalInitialStories.ts) opts Regional EN/HI selection into backend `ready` translations only when both the requested locale's title and body are present. Regional cards, compact initial props and their initial sidebar fallback share that policy and render the selected fields, including a real requested-language summary when available. Gujarati selection and the shared strict policy used by Home and global Latest do not opt in.
- [The Regional query proxy](./pages/api/public/regional/index.ts) and the initial ISR loader share [regionalFeedSource.ts](./lib/regionalFeedSource.ts) for primary eligibility and fallback resolution. They retain `/api/public/regional` as primary and fall back to `/api/public/news?category=regional` with both requested-language parameters. Only this fallback treats exact `regional` News as Gujarat without redundant state metadata; district filtering and the existing publication/language selectors remain in place. Initial loading retains its four-second deadline and propagates source failures so failed background regeneration keeps the previous ISR page.
- Regional Gujarat uses fixed 30-item backend pages. Pagination metadata is captured before frontend filtering; completely filtered pages are advanced within the existing read deadline. Load More appends the next page using the existing locale/slug selection, chronology, and ID dedupe. The 60-second refresh rereads the loaded range sequentially in fixed-size pages, retaining the previous list if any read fails. Unpaged Regional callers keep their existing response contract.
- Only Regional Gujarat initial props use [regionalListingStories.ts](./lib/regionalListingStories.ts): display/filter/identity/publication fields, the resolved cover URL, and the existing reading-time calculation are retained. Full bodies, other-language payloads, and duplicate metadata are omitted. A bounded real requested-language content excerpt and existing normalized translation state preserve the strict locale checks after hydration; eligibility is checked against full records before projection. Browser responses remain full records for the existing body-search behavior.
- The eight non-Regional ordinary categories opt into bounded News pagination through [ordinaryCategoryPagination.ts](./lib/ordinaryCategoryPagination.ts) and [categoryFeed.ts](./lib/categoryFeed.ts): National uses 20 records per page; International, Business, Science & Technology (`tech`), Tech & Gadgets, Sports, Lifestyle and Glamour use 30. The explicit browser request header activates a single requested-language primary page in [the News proxy](./pages/api/public/news.ts), without its legacy translation-group widening. Other consumers, including Regional, Home and protected categories, do not opt in and retain their existing contracts.
- [Faith & Culture](./pages/faith-culture/index.tsx) separately opts into its backend-owned strict contract through [faithCulturePagination.ts](./lib/faithCulturePagination.ts). Initial ISR and subsequent reads use `category=faith-culture`, matching `lang`/`language`, and fixed `page=N&limit=30`. Its dedicated browser header bypasses locale widening and proxy regrouping without changing the ordinary-category allowlist. All five pagination fields are required and validated before frontend filtering; Load More reads only the next page, retaining metadata even when local search hides that page. Publication ties retain backend order, appends reuse ID/logical-story dedupe, and query changes abort/reset reads. Existing compaction and 60-second ISR/polling remain; refresh replaces the loaded range only after all fixed-page reads succeed. Expected initial-build read failures render a localized unavailable/noindex page without validated pagination, not an empty successful archive. Hydration retries the real feed, and the existing ISR/polling can recover it. Stale/on-demand failures still throw to retain previously generated content; unexpected build errors also remain fatal. Genuine empty pages require a successful validated response.
- Faith-only topic chips use the seven stable codes in [faithCultureTopics.ts](./lib/faithCultureTopics.ts) and the existing runtime EN/HI/GU dictionaries. The URL's validated `topic` is forwarded to the backend on every fixed-page read; topic membership is not filtered locally. All omits `topic` and retains its ISR seed, while a selected topic excludes that seed and remounts the feed to cancel/discard the previous topic's pages. Shallow topic navigation preserves search and locale, existing language switching preserves the query, and invalid or repeated topic values fall back to All. Selected-topic empty results use the existing empty-state UI with filter-specific copy.
- [CategoryStoryHierarchy.tsx](./components/category/CategoryStoryHierarchy.tsx) keeps supplied read failures visible even after the feed is exhausted, suppressing its completion message while retaining existing stories. An exhausted feed does not expose a next-page retry. [CategoryFeedPage.tsx](./components/CategoryFeedPage.tsx) retains the previous warning during background recovery and clears it only after a successful read.
- [CategoryFeedPage.tsx](./components/CategoryFeedPage.tsx) and [National](./pages/national/index.tsx) append unique records, retain backend exhaustion metadata captured before filtering, and reset/abort reads when their query context changes. Existing local search/topic/state predicates are preserved; completely filtered pages advance within the read deadline rather than implying exhaustion. Refreshes use fixed pages and retain the loaded range until its replacement succeeds; polling remains 60 seconds for shared pages and 45 seconds for National. Paginated category browser reads allow six seconds for the News proxy hop; Regional browser reads allow twelve seconds around the Regional proxy's existing ten-second default. Server reads retain their four-second category/Regional and eight-second National budgets. Proxy deadlines, HTTP error responses, initial-prop compaction and 60-second ISR are unchanged. Offset pagination is not a snapshot across concurrent publication/deletion.
- [articleBody.ts](./lib/articleBody.ts) handles article-body content and controlled embeds; [seo.ts](./lib/seo.ts) centralizes SEO helpers. [The sitemap handlers](./pages/api/sitemap.ts) and [news sitemap handler](./pages/api/news-sitemap.ts) serve the corresponding rewritten public URLs.
- Article links, SSR redirects and canonical/OG URLs use [articleSlugs.ts](./lib/articleSlugs.ts). A locale-scoped Backend `canonicalSlug` (including an explicit same-article ObjectId fallback) wins; otherwise the resolver uses an explicit locale slug, an owned legacy slug, or the ObjectId. Foreign scripts, foreign-owned aliases and unsafe URL segments are rejected. Locale-owned legacy Latin transliterations remain compatible with the Backend contract. Unicode segments are encoded once; published source records, aliases, IDs, groups and publication dates are never rewritten by the Frontend.
- The [public News boundary](./lib/publicNewsApi.ts) retains resolved-locale and routing metadata. Detail proxies and mounted article refreshes use an authoritative locale-resolved detail rather than replacing it with an unlocalized group row that lacks collision/availability metadata. Legacy responses retain their existing group-resolution and lifecycle behavior; ID paths try the supported ID detail endpoint first.
- [Server-only article SEO reads](./lib/articleSeo.server.ts) verify advertised peer editions through read-only ID detail requests, checking publication, locale and story identity before emitting reciprocal hreflang. Availability flags alone do not expose foreign content or create alternate URLs. Peer reads run concurrently within the existing remaining SSR allowance (at most 1.5 seconds); failed peers are logged and omitted, never invented. English is `x-default` when available.
- [Both XML sitemaps](./lib/sitemap.server.ts) page the unfiltered strict EN/HI/GU public News feed in 40-record batches, at most two locales at a time. All pages, totals and distinct row IDs must agree before an inventory is accepted. Only indexable editions participate; native editions take precedence over same-story cached translation aliases. The main XML emits reciprocal canonical links, including self and `x-default`; the news XML retains its two-day publication window. Failed reads never become partial XML: the main handler can reuse a bounded last complete snapshot without extending its cache lifetime; otherwise the response is `503`, `Retry-After`, `no-store`.
- Social metadata is server-rendered by [the article page](./pages/news/[slug].tsx) using [shared SEO helpers](./lib/seo.ts): localized title/description, canonical `og:url`, `og:site_name=News Pulse`, edition locale, complete image properties and Twitter Card metadata. Only public, visible editions emit article metadata; explicit private/restricted lifecycle markers remain ineligible. Source-edition SEO overrides and other editions' graphics are not borrowed. Stored editorial canonical fields cannot override the verified locale route.
- [Server-only preview diagnostics](./lib/socialPreviewDiagnostics.server.ts) emit bounded `[social-preview]` JSON records for article and Smart Share HTML requests: one render record and one correlated backend record per primary detail-proxy response (normally two records total). Next data/prefetch requests, ordinary API polling, recommendations and unrelated routes are not traced. Each page request gets a generated UUID in `x-newspulse-preview-id`; the validated internal `x-newspulse-preview-trace` links only its ID/slug proxy reads and is not forwarded to the Backend. Backend records contain actual response status and header/body-read duration, capped at eight read details with a total count, plus safe image failure/cache flags. Render duration runs from SSR-loader entry through response finish, excluding earlier middleware/queue time; interrupted responses are explicit. Open Graph completeness is derived from the same metadata helper used by the renderer, and image selection is recorded only as verified article image, official fallback or none. Logs never contain article IDs, URLs, titles/bodies, image URLs, reader identifiers, headers, credentials or error messages/stacks. Existing deadlines, caches, visibility checks and error responses are unchanged; diagnostics do not establish receiving-platform preview success.
- [Social image selection](./lib/articleSocialImage.ts) prefers valid edition-owned editorial OG images, then the actual cover, without changing article-displayed images or uploaded originals. Only unsigned public Cloudinary `image/upload` assets without supplied transformations/query parameters are remotely verified; unsupported sources use the official branding fallback. The generated HTTPS JPEG uses 1200 x 630 white padding, preserving the whole image and its aspect ratio. [Server verification](./lib/articleSocialImage.server.ts) measures the body below 300,000 bytes, validates JPEG format/dimensions and decoding, rejects redirects, bounds streaming/download work and lowers quality only for oversized results. It exposes no arbitrary-URL image endpoint.
- Public ID, slug and legacy group detail reads attach the verified image descriptor only after locale/public eligibility. Optional image work uses at most 1.5 seconds inside the existing four-second read allowance, with response headroom; failures are logged and use the [optimized official branding derivative](./public/brand/news-pulse-social.jpg). The original [branding PNG](./public/brand/news-pulse-final-logo.png) and publisher schema logo are unchanged. Only image verification is cached (bounded, one hour for versioned uploads, one minute otherwise, 15 seconds for failed reads); article visibility/content and detail HTML retain their existing no-store behavior. Existing Save Update/public-version refreshes consume fresh metadata, and replacement/versioned image URLs select a new cache entry. Removal flags override stale cover aliases.
- Smart Share links use [the shared URL builder](./lib/newsRoutes.ts): `/s/<articleId>`, `/hi/s/<articleId>` and `/gu/s/<articleId>` with the existing public ObjectId identity. [The short route](./pages/s/[slug].tsx) retains the article page's parameter name for its refresh lifecycle but accepts IDs only. It uses the same published locale resolution, full article renderer, [Back navigation](./src/components/navigation/SmartBackButton.tsx), optimized metadata and no-store reads for visitors and crawlers, without a redirect or a slug fallback. Original article canonicals, `og:url`, reciprocal hreflang and sitemap entries stay on the existing `/news/` routes. Missing, pending, invalid and nonpublic editions return 404; unavailable reads retain the article's observable 503 state. The short namespace bypasses editorial SEO redirects, and its selected locale takes precedence over preference cookies and legacy `?lang=` queries during hydration. No database, external shortener or publishing/revalidation workflow change is introduced.
- Public [article detail](./pages/news/[slug].tsx) mounts one [ArticleShareBar](./components/ArticleShareBar.tsx) trigger below the headline/byline for visible articles. Its nonmodal popover has a row of Facebook, X, WhatsApp, LinkedIn and Telegram icons, followed by full-width Copy link and More options rows. Every action uses the locale-specific Smart Share URL and article title, retaining the canonical link only when a supported public ID is absent. Native-share clipboard fallback and cancellation behavior are unchanged. Labels and feedback are localized. ### Published settings and live refresh

```text
Backend published settings
  -> /api/public/settings
  -> src/lib/publicSettings normalization
  -> PublicSettingsProvider
  -> homepage modules, tickers, Live TV, and other consumers

Backend public version
  -> usePublicVersion
  -> publicDataRefresh event
  -> subscribed consumers refetch
```

[pages/api/public/settings.ts](./pages/api/public/settings.ts) supports two distinct contracts:

- Without `keys`, it reads published settings, tries compatibility backend endpoints, and can return local/default fallback settings marked with `settingsSource: 'fallback'`.
- With `keys`, it reads an allowlisted set of file-backed feature flags through [lib/publicSettings.ts](./lib/publicSettings.ts).

The published-settings types, normalization, and client fetcher are in [src/lib/publicSettings.ts](./src/lib/publicSettings.ts). They are not the same module as the root feature-flag helper. [PublicSettingsContext.tsx](./src/context/PublicSettingsContext.tsx) seeds from page props, deduplicates loads, and retains existing settings during background refresh.

[usePublicVersion.ts](./hooks/usePublicVersion.ts) polls and responds to focus/visibility changes. It dispatches through [publicDataRefresh.ts](./lib/publicDataRefresh.ts) when a backend-confirmed version changes; fallback versions must not be interpreted as a publish.

File-backed settings are compatibility/fallback behavior, not evidence that a serverless filesystem is a durable production database. Successful fallback rendering also does not prove the backend is healthy.

## 6. Tooling and maintenance boundaries

- [jest.config.js](./jest.config.js) configures Jest with jsdom, fetch setup, and TypeScript transforms. The [tests](./__tests__/) cover environment separation, localization, news visibility, settings, reporter auth, consent, and public integrations. They are not a certificate for a live backend.
- [tsconfig.json](./tsconfig.json) includes the root page/component/helper trees, `src`, and tests. It enables `strictNullChecks` but not full `strict` mode.
- [tailwind.config.js](./tailwind.config.js) currently scans the root page and component trees, not all `src` files. New utility classes need an appropriate scanned source or an intentional configuration change.
- [.storybook/main.ts](./.storybook/main.ts) configures the separate Storybook workflow. Root application tests use Jest.
- `npm run lint` is a known script mismatch: [package.json](./package.json) still calls the removed `next lint` command. Next.js 16 builds do not run linting. See [rules.md](./rules.md) for validation expectations rather than treating a build as a lint result.
- [.gitignore](./.gitignore) excludes local environment files, generated output, local labs, and the local documentation directory. Durable project documentation belongs in the tracked root documents.

Update this map when ownership, request flow, or integration boundaries change. Keep exact payload details in types/tests and transient verification results out of architecture documentation.
